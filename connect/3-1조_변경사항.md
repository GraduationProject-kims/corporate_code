# 3-1조 변경 사항 (교수님 프로토타입 기준)

녹화 영상 평가와 실시간 서버가 **같은 판정 코드(judge.py)** 를 쓰도록 합친 것.
폰 앱(Kotlin)은 고치지 않았음. 실행 방법도 README 10-1과 같음.

## 파일

| 파일 | 무엇 |
|---|---|
| `judge.py` (추가) | 판정 설정값·함수. 연수 코드(run_model.py, 명세 4.1~4.11)의 함수를 그대로 옮김. **판정·모델 설정은 여기서만 바꿈** |
| `server.py` (수정) | 실시간 서버. 박스 거리·경로 장애물·경고·방향·모터를 judge.py로 계산. 회신 형식은 그대로 + `judge` 항목 추가 |
| `live_record.py` (추가) | 실시간 시행 기록 (frames.csv는 녹화 평가와 같은 형식 + latency.csv) |
| `run_model.py` (연수 코드) | 녹화 영상 평가. 판정 부분만 judge.py를 쓰게 바꿈 (결과는 바꾸기 전과 같음) |
| `tools/send_video.py` (추가) | 폰 없이 녹화 영상을 서버로 보내 보는 시험용 |

## 실행

```bash
conda activate blind-helper
cd server
RUNNER=내이름 uvicorn server:app --host 0.0.0.0 --port 8001
```

- 서버 터미널에 시행ID(예: `1019_front_01`) 입력 + Enter → 기록 시작, 그냥 Enter → 끝
- 결과: `runs/<RUNNER>/<시행ID>_<MMDD>_<HHMMSS>/` (run_meta.json, frames.csv, summary.json, latency.csv)
- 녹화 영상 평가는 전과 같이: `python run_model.py --video 1019_front_01.mp4 --runner 내이름`

## server.py에서 바뀐 점

- 맥북 버전의 장치 자동 선택(DEVICE)과 시연 사이트 전송(live_mirror) 유지. 사이트에는 원래와 같은 형식(원본 크기 이미지, 원래 항목만)으로 보냄. `SITE_JUDGE=1`이면 judge 항목 추가
- 모델 설정(`MODEL_PATH`, `CONF_THRES` 0.4, `IMG_SIZE` 416, `DEPTH_MODEL`)은 judge.py 값을 씀. 모델 교체(README 11장)도 judge.py에서
- 받은 프레임을 폭 640으로 줄여서 추론·판정 (녹화 평가와 같게). 폰에 보내는 박스 좌표는 원본 크기로 되돌림
- 박스 거리: 박스 중심 7×7 중앙값 → judge.box_distance (박스를 20% 줄인 영역의 하위 30%)
- 회신 JSON에 `judge` 추가: `warn`, `obstacle_m`, `source`(DEPTH/YOLO), `direction`, `motor`, `vib_count`. `dets`는 폰 파싱 때문에 맨 끝에 둠
- 뷰어 창: 녹화 평가와 같은 표시 (경로 사각형, 장애물 거리, 모터, 방향 칸, 기록 중이면 REC)
- `model.fuse()` 뺌 (녹화 평가와 같게)

## 알아둘 것

- **폰 자체 진동·소리는 여전히 앱 안의 원래 판정(ObstacleAlarm.kt)으로 울림.** 우리 판정 결과는 서버 화면, 회신의 `judge` 항목, frames.csv에 나옴. 폰이 우리 판정으로 진동하게 하려면 앱에서 `judge.motor`를 읽게 고쳐야 함 (진동 장치 연결 때 같이)
- `DEPTH_EVERY_N`(server.py)과 `--depth_every_n`(run_model.py)은 같은 값이어야 결과가 같음 (기본 1)
- 실시간은 서버가 못 따라가면 밀린 프레임을 버리고 최신 프레임만 처리함. 그래서 같은 장면이라도 녹화 평가보다 처리 프레임 수가 적을 수 있음
- 클래스 모드: 실행할 때 `TARGET_LABELS=bottle`을 붙이면 그 클래스 YOLO 박스만 장애물로 봄 (기본은 깊이 기반, 결과 동일 확인)
