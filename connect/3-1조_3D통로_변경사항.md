## 3D 통로

사용자 앞 공간을 미터로 정한다: 폭 `PATH_WIDTH_M`(0.8), 높이 `CORRIDOR_BOTTOM_M`~`CORRIDOR_TOP_M`(0~카메라+0.2), 길이 `WARN_M`(3).

1. 타겟 박스의 거리 `dist`는 지금과 같다 (박스를 줄인 영역의 depth 하위 30%).
2. 초점거리 `f = (W/2) / tan(HFOV/2)`로 박스 네 변을 그 거리의 미터 좌표로 바꾼다.
   - 가로 `X = (u - W/2) × dist / f` (오른쪽 +)
   - 높이 = `CAMERA_HEIGHT_M` − 카메라 아래쪽 거리 (`CAMERA_PITCH_DEG`만큼 돌려서 계산)
3. 물체가 통로와 가로·세로 모두 `CORRIDOR_MIN_OVERLAP_M`(5 cm) 이상 겹치면 경로 안이다.
4. 경로 안이고 `dist < WARN_M`이면 경고한다.
5. 방향: 물체 중심 X가 −0.15 m보다 왼쪽이면 왼쪽, +0.15 m보다 오른쪽이면 오른쪽, 그 사이는 정면. 0.15는 옆 접근 시행(30 cm)과 정면(0 cm)의 중간이다. 모터 대응(`MOTOR_MAP`)과 방향 유지는 그대로다.

같은 화면 위치라도 가까우면 통로 안, 멀면 통로 밖이 될 수 있다. 화면 고정 사각형과 가장 다른 점이다. 화면의 3분할 선은 없어지고 통로 투영이 그려진다. 빨간/초록 사각형이 3 m 지점 단면이다.

## 실험 전에 잴 값

| 값 | 기본 | 틀리면 |
|---|---|---|
| `HFOV_DEG` | 70 (미확인) | 좌우 거리가 전부 비례해서 틀어짐. **가장 중요** |
| `DEPTH_SCALE` | 1.0 | 거리와 좌우 거리가 같이 틀어짐. YOLO26-depth 기준으로 다시 잴 것 |
| `CAMERA_HEIGHT_M` | 1.55 | 높이 판정이 틀어짐. 착용자마다 줄자로 |
| `CAMERA_PITCH_DEG` | 0 | 앞 3 m에서 10°면 높이가 약 0.5 m 틀어짐. 바닥까지 포함한 통로라 수트케이스는 영향이 작음 |

**화각 재는 법**: 폭을 아는 수트케이스를 정확히 2 m 앞에 두고 정지 촬영한 뒤, 타겟 `frames.csv`의 `box_w_px`(원본 픽셀)로 계산한다.

```
HFOV = 2 × atan( 영상 가로 픽셀 × 실제 폭(m) / (2 × box_w_px × 실제 거리(m)) )
```

여러 장의 중앙값을 쓴다. 비스듬히 놓으면 박스가 넓어지니 정면으로 둔다.

**영상 종류별로 따로 잰다.** 지금까지 run 기록에서 실시간은 360×640(가로/세로 0.56), 녹화는 1080×1432·1442(0.75)로 비율이 다르다. 잘린 범위가 다르면 화각도 다르다.

## 결과 파일

```
runs/<runner>/<시행ID>_<MMDD>_<HHMMSS>/
├─ run_meta.json, frames.csv, summary.json, (실시간) latency.csv   ← 전체, 형식 그대로
└─ target_suitcase/
   ├─ run_meta.json    전체와 같음 + target_labels, target_schema_version
   ├─ frames.csv       타겟 탐지 1개당 1줄 (타겟을 잡은 프레임만)
   ├─ latency.csv      타겟을 잡은 프레임의 지연. 녹화는 yolo_ms·depth_ms만 있고 나머지는 빈칸
   └─ summary.json     탐지율·첫 경고 등 요약
```

전체 `frames.csv`와는 `frame_idx`로 이을 수 있다.

### target_suitcase/frames.csv

| 칸 | 값 |
|---|---|
| `trial`, `frame_idx`, `t_ms` | 전체 frames.csv와 같음 |
| `det_idx`, `n_targets` | 그 프레임 안 탐지 번호, 타겟 수 |
| `label`, `conf` | 클래스, 확률 |
| `x1 y1 x2 y2`, `box_w_px`, `box_h_px`, `box_cx`, `box_cy` | 박스 (원본 픽셀) |
| `box_clipped` | 1이면 화면 끝에 잘림 → 크기·중심 부정확 |
| `dist` | 박스 거리(m) |
| `depth_fresh` | 1이면 이 프레임에서 새로 계산한 depth, 0이면 직전 depth (`depth_every_n` > 1일 때) |
| `forward_m` | 사용자 기준 앞 거리(m). 숙임각 0이면 `dist`와 같음 |
| `x_left_m`, `x_right_m`, `x_center_m` | 통로 중심선 기준 가로 위치(m, 오른쪽 +) |
| `top_m`, `bottom_m` | 바닥 기준 높이(m) |
| `width_m`, `height_m` | 추정 크기(m). 실제 크기와 비교하면 화각·거리 점검이 됨 |
| `overlap_x_m`, `overlap_y_m` | 통로와 겹친 길이(m). 음수면 그만큼 떨어져 있음 |
| `lateral_ok`, `vertical_ok` | 가로·세로 겹침 통과 |
| `in_path` | 이 프레임 판정에 쓴 경로 안 여부 (`PATH_MODE=2d`면 화면 사각형 기준) |
| `in_warn_range` | `dist < WARN_M` |
| `is_warn_target` | 이 박스가 경고 대상 |
| `level`, `level_name` | 그 프레임의 경고 |
| `direction`, `motor`, `vib_count` | 경고 대상 줄에만 |
| `yolo_ms`, `depth_ms` | 처리 시간 (depth 안 돌린 프레임은 빈칸) |

### target_suitcase/summary.json 주요 칸

`frames_total`, `frames_detected`, `detection_rate`, `longest_miss_frames`(연달아 놓친 최장 프레임), `frames_in_path`, `frames_warned`, `first_detection`, `first_in_path`, `first_warning`, `conf_median`, `dist_median`, `width_m_median`, `height_m_median`(잘린 박스 제외), 지연 중앙값, `focal_px`, `corridor`(쓴 통로 설정), `expected_dir`, `gt_2m_sec`, `note`

## 팀 규칙 관련

- 전체 `frames.csv` 칸은 안 바꿨다. `run_meta.json`의 `alarm_constants`에는 통로 설정 칸이 늘었고 `CHOICES`의 2-5·2-7 값이 달라진다. run_model.md 10장 규칙상 `SCHEMA_VERSION` 3으로 올릴지 팀에서 정한다 (지금은 2 그대로).
- `run_model.md`의 3~4장은 깊이 기반 판정 기준 설명이다. 3D 통로 모드의 경로·방향 규칙은 이 문서가 기준이다.
